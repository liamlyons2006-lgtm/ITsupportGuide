## Before you start

- Write notes as you work, not from memory at the end.
- Assume a different tech will read them, and that the user may read them too.

## Steps

1. State the problem in one line, in the user's words.
2. Record what you checked and the result of each check.
3. Record each change you made, with the exact setting or command.
4. Paste exact error text and event IDs rather than paraphrasing them.
5. Note the current status and the next step if it is not resolved.
6. Keep it factual and neutral. No blame, no opinions about the user.

:::tip
A good test: could a colleague take over this ticket from your notes alone,
without calling you? If not, add what is missing.
:::

:::caution
Never put passwords, secrets, or personal data in ticket notes. Record that a
password was reset, not what it was set to.
:::

## Verify it worked

- The notes show the problem, what you tried, what you changed, and the outcome.
- Someone else could continue the ticket without contacting you.
- No secrets or sensitive personal data are in the notes.
